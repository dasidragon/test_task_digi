# GeoLayer — Метеорологический мониторинг (Бишкек)

Интерактивное веб-приложение для визуализации и анализа пространственно-временных метеорологических данных на карте Mapbox GL JS с временной шкалой (Timeline) и аналитическими графиками Recharts.

---

## Технологический стек

| Категория | Технология | Обоснование выбора |
|---|---|---|
| **Core** | React 19 + TypeScript | Строгая типизация, современный компонентный подход |
| **State Management** | **Vedro** | Единый реактивный источник правды приложения |
| **Картография** | **Mapbox GL JS** | Аппаратный WebGL-рендеринг, поддержка GeoJSON, тепловых карт и 3D-экструзии |
| **Визуализация данных** | **Recharts** | Декларативные графики временных рядов с двусторонней синхронизацией |
| **UI Framework** | **Ant Design (antd)** | Стандартные компоненты, адаптивный Layout, доступность |
| **Сборка** | **Vite** | Мгновенный HMR, быстрая сборка, алиасы путей `@/*` |

## Границы ответственности модулей

```
┌────────────────────────────────────────────────────────┐
│                   UI Components                        │
│ (LayerControl, Timeline, 3x Analytics Cards, MapView)  │
└───────────────┬────────────────────────▲───────────────┘
                │                        │
       (dispatch actions)          (useSelector)
                │                        │
                ▼                        │
┌────────────────────────────────────────┴───────────────┐
│                 Vedro State Manager                    │
│      (selectedTimeIndex, layers, layerData)            │
└───────────────┬────────────────────────────────────────┘
                │
                ▼
┌────────────────────────────────────────────────────────┐
│             Services & Data Transformers               │
│  (layer.service.ts async mock API, geo.service.ts)     │
└────────────────────────────────────────────────────────┘
```

1. **UI Components**: Не содержат прямой бизнес-логики. Получают данные через `useSelector` и инициируют изменения через типизированные функции (`setSelectedTimeIndex`, `toggleLayerVisibility`).
2. **Vedro Store**: Хранит единое состояние приложения (выбранное время, статус загрузки, видимость слоев, кэшированные временные ряды).
3. **Mapbox GL Integration**: Карта инкапсулирована в `useRef` и обновляется императивно через `source.setData()` при изменении времени без дорогостоящего React-ре-рендера всего DOM-дерева.
4. **Recharts Analytics**: Декларативно отображает временные ряды и синхронизирует выбранную точку с картой и таймлайном.

## Почему Mapbox GL JS?

Выбор **Mapbox GL JS** обусловлен следующими инженерными факторами:
1. **WebGL-ускорение**: Обработка тысяч координат, динамических радиусов и тепловых карт силами GPU с частотой 60 FPS.
2. **Декларативное обновление данных**: Метод `source.setData(geoJson)` позволяет обновлять слой за доли миллисекунды без пересоздания карты.
3. **Поддержка 3D объектов**: Встроенный тип слоя `fill-extrusion` позволяет легко визуализировать 3D-модели (например, 3D метеорологическую вышку в Бишкеке) с учетом высоты, перспективы и наклона камеры (`pitch`, `bearing`).
4. **Векторные стили**: Высокое качество отображения подписей, дорог и ландшафта на любых уровнях масштабирования.

```

        setSelectedTimeIndex(dispatch, newIndex)
                         │

                         │

        ▼                                 ▼
[useMapboxLayersSync]              [Recharts Cards]
```

## Потенциальные проблемы производительности и решения

1. **Многократные ре-рендеры React**: Карта инкапсулирована через `useRef`. При переключении таймлайна React не перерисовывает DOM-холст карты, а хук `useMapboxLayersSync` вызывает нативный WebGL-метод `map.getSource().setData()`, работающий на GPU со скоростью 60 FPS.
2. **Race conditions при быстром переключении**: В `useLayerLoader.ts` и `layer.service.ts` запросы изолированы через флаги подписки и Abort-логику, гарантируя, что устаревший ответ не перезапишет свежие данные.
3. **Кэширование временных рядов**: Снимки на весь день (`LayerTimeSeries`) кэшируются в памяти Vedro store, поэтому переключение времени (например, при автовоспроизведении) происходит за 0 мс без сетевых задержек.

## Масштабирование на 30–100+ GIS-слоев

1. **Стейт-менеджмент**: Структура в Vedro организована через словарь `Record<LayerId, LayerSnapshot>`, где добавление нового слоя — это добавление одного объекта конфигурации без изменения логики ядра.
2. **Картография**: Для 100+ слоев и миллионов точек GeoJSON переводится на векторные тайлы (MVT / Mapbox Vector Tiles) или Deck.gl / WebGL инстансинг с загрузкой только видимого вьюпорта (BBOX).
3. **UI и аналитика**: Виртуализация списка слоев и аналитических карточек через `react-window` / `antd Table virtual scroll` для предотвращения перегрузки DOM.

## Сознательные компромиссы (Trade-offs)

1. **Клиентская генерация данных вместо сервера**: Данные генерируются через асинхронный Mock-сервис для демонстрации работы со сложными снимками без необходимости запуска внешнего бэкенда.
2. **Компактная сетка станций**: Для наглядности метеостанции привязаны к реальным районам Бишкека (Ала-Тоо, Асанбай, Кызыл-Аскер, Восток-5, ТЭЦ, Джал и др.).
3. **MapLibre GL вместо платного токена Mapbox**: Использован полностью совместимый открытый движок `maplibre-gl` с тайлами CARTO Positron, что обеспечивает работу приложения "из коробки" без регистрации приватных API-ключей.
